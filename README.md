# AlterForm 
## Self-hostable furry art gallery web app

Tired of every new furry site having shitty moderation? Me too. So here's my solution. I'm building this FOSS web app that is designed to be super easy to deploy, containerized and all that fun stuff. I'm not quite there yet.
No more purity lobbies, no more payment processors. No more spinal charts. You host, you moderate. I host a flagship instance that will pretty much have the same rules as FA. Federation is down the line. Think Bluesky, but for FA.

## I need your help
This is a free and open source project under AGPL 3.0 and I really could use some help on the visual assets. I would love nothing more than to see the folks in this community take this project and run with it. clone it, add features, fix bugs. I would like it to grow beyond me. I'm not in this for money. I just want to break the furry platform curse and I don't think any single monolithic instance is conducive to that end. 

## No, I'm not using AI
I tried that with a previous version I prototyped and it didn't really work out. The codebase felt bloated and full of overly redundant concurrency checks, hacky css tricks and Entity Framework abuse that I just couldn't deal with it and so I'm starting over and writing the whole thing by hand. My thoughts on the role of AI in programming can basically be boiled down to this: Software that needs to transmit and store sensitive data securely needs to be fully understood by a donkey who is accountable for it. That being said, things like fixing bugs, SAST, and DAST, are all widely accepted use cases for AI in software development and that is true for this project as well. Files like `.gitignore` and `Program.cs` as well as several others are procedurally generated by the dotnet sdk, not AI.

# The Stack

 1. C# / dotnet 11
 2. Blazor WASM
 3. Radzen.Blazor
 4. Entity Framework
 5. PostgreSQL
 6. AspNetCore.Identity

# Where I'm at
Integrating Entity Framework and rebuilding the data model from scratch. Table-per-heirarchy, DataAnnotationsValidator, 
ApiController, HttpClient, and a user class that inherits from IdentityUser. DbContext, initial migrations, all the good stuff basically.
